# How to Create a Workflow Node (React Flow)

This guide outlines the standard procedure for creating and registering custom Workflow nodes in the Quan ERP frontend using React Flow (`@xyflow/react`) and the unified `WorkflowNode` component.

## 1. Node Structure

All nodes should receive the following standard props from React Flow:
```typescript
{ id: string, data: GenericNodeData, selected?: boolean }
```

The `data` prop typically follows this type (or an extended version of it):
```typescript
export type GenericNodeData = {
    defination?: WorkflowNodeDefination;
    label?: string;
    subLabel?: string;
    icon?: React.ReactNode;
    iconBg?: string;
    values?: any;
    hasInput?: boolean;
    hasOutput?: boolean;
};
```

## 2. Basic Node Implementation

For simple standard nodes (without custom handles), you can utilize the `createDefaultWorkflowNodeComponent` utility from `@quan-erp/base-frontend`.

```tsx
import { AlarmClock } from "@icon-park/react";
import metadata from '../../../module.metadata.json' with { type: 'json' }
// metadata.name === "my-plugin"
import { createDefaultWorkflowNodeComponent } from "@quan-erp/base-frontend";

export const MyTriggerWorkflowNode = createDefaultWorkflowNodeComponent(
    {
        defaultIcon: <AlarmClock size={20} />,
        defaultLabel: 'On My Item Created',
        pluginName: metadata.name,
        defaultIconBg: 'bg-pink-50 dark:bg-pink-950/40 text-pink-600 dark:text-pink-400',
        hasOutput: true,
        hasInput: false
    }
);
```

## 3. Advanced Node Implementation

For nodes that require custom styling, multiple input/output handles, or dynamic rendering based on connections, use the `WorkflowNode` component wrapper.

### Important: Imports
`WorkflowNode` MUST be imported from `@quan-erp/base-frontend`. 
Do NOT import it using relative paths like `../../component/workflow-node.tsx` when you are outside the `base` frontend.

### Step 3.1: Define the Component

```tsx
import React from 'react';
import { Handle, Position } from "@xyflow/react";
import { Tool } from "@icon-park/react";
import { WorkflowNode } from "@quan-erp/base-frontend";
import metadata from '../../../module.metadata.json' with { type: 'json' }
// metadata.name === "my-plugin"

export type MyNodeData = {
    defination?: any;
    label?: string;
    subLabel?: string;
    icon?: React.ReactNode;
    iconBg?: string;
    values?: any;
};

export const MyWorkflowNode = ({ id, data, selected }: { id: string; data: MyNodeData; selected?: boolean }) => {
    return (
        <WorkflowNode
            pluginName={metadata.name}
            id={id}
            data={data}
            selected={selected}
            defaultIcon={<Tool size={18} theme="outline" />}
            defaultLabel="My Node"
            defaultIconBg="!w-9 !h-9 !rounded-full bg-yellow-50 dark:bg-yellow-950/40 text-yellow-600 dark:text-yellow-400 shadow-sm !text-lg"
            className={`!rounded-full w-[7rem] aspect-square p-3 gap-1 ${
                selected
                    ? '!border-yellow-500 shadow-md ring-4 !ring-yellow-500/10'
                    : 'hover:!border-yellow-200 dark:hover:!border-yellow-900'
            }`}
        >
            {/* Custom handles go inside the WorkflowNode wrapper as children */}
            <Handle
                type="source"
                id="output"
                position={Position.Top}
                className={`!w-4 !h-[6px] !bg-yellow-300 dark:!bg-yellow-700 !border-0 !rounded-[2px] !-top-[3px] transition-colors ${selected ? '!bg-yellow-500' : 'hover:!bg-yellow-400'}`}
            />
        </WorkflowNode>
    );
};
```

## 4. UI Standards and Styles

When building nodes with `WorkflowNode`:
- The `WorkflowNode` component automatically provides the card container (`bg-card`), base corners, the hover "Play" button, and the "Delete" button.
- You can override classes via `className`. Use `!` (important) if your overrides conflict with the default classes generated by `WorkflowNode`.
- Use `defaultIconBg` to style the icon wrapper.
- Add `<Handle>` elements as `children` to the `WorkflowNode`.

## 5. Registering the Node (Plugin Approach)

Plugins must register their custom nodes dynamically when the plugin initializes. You can use the globally exposed `workflowNodes()`, `workflowGenericOnSave()`, and `workflowGenericOnLoad()` utilities from `@quan-erp/base-frontend`.

```tsx
import { workflowGenericOnLoad, workflowGenericOnSave, workflowNodes } from "@quan-erp/base-frontend";
import { MyWorkflowNode } from "./workflow/my.workflow-node.js";
import metadata from "../module.metadata.json" with { type: "json" };
// metadata.name === "my-plugin"

// Inside your Plugin initialization / setup function:
workflowNodes().push({
    type: `${metadata.name}/my-node`, // Must match the `type` returned by the backend `getDefination()`
    element: MyWorkflowNode,
    onSave: workflowGenericOnSave(),
    onLoad: workflowGenericOnLoad()
});
```
